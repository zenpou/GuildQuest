# GuildQuest 設計書(MVP)

> 2026-10-03: この文書は初期Coreの設計記録。現在の段階チュートリアル・14章・キャラクター設定は [物語設計](STORY-DESIGN.md)、Web/PWAと端末展開は [プラットフォーム設計](PLATFORMS.md) を参照。

## 1. 企画概要
異世界に転移した「戦えない主人公」は、なぜか他人のステータスが見える。見たまま冒険者を配置しているだけなのに、
周囲は「才能を見抜く天才」と深読みして評判が膨らみ、小さな事務所が有名ギルドへ育っていく。
**冒険者を見て → 配置を悩み → 派遣し → ログを読んで笑う** 日常系ライトコメディ経営シミュレーション。
PCブラウザ向け(TypeScript + Vite)、シングルプレイ、30日で「灰竜の討伐」を目指す。死亡なし・ゲームオーバーなし。

## 2. コアループ
募集を見る → ステータス確認 → 雇用 → (転職・編成) → 依頼選択 → 方針・消耗品 → 派遣
→ 自動探索(結果は帰還日に確定) → 日を進める → 帰還・ログ閲覧 → 報酬/負傷/関係値 → 給与・維持費 → 施設強化 → 次の編成

## 3. MVP 機能一覧
| 区分 | 内容 |
|---|---|
| 冒険者 | seed生成。8能力・3職業の適性・性格6・特性10(一部は未判明「？？？」)・成長率・給与・忠誠・疲労・負傷 |
| 職業 | 剣士 / 狩人 / 術師(転職は無料。適性が噛み合うと伸びる=「見る」遊び) |
| 探索地 | 東の森 / 古い坑道 / 灰竜の遺跡 |
| 敵 | 7種(ボス2) |
| 依頼 | 11種(討伐・採取・探索・ボス)。評判で解放 |
| 探索イベント | 16種(戦闘・宝箱・薬草・罠・迷子・商人・怪我人・遺跡・隠し通路・会話・喧嘩・協力ほか)+野営 |
| 戦闘 | 自動ターン制。スキル・敵AI・戦闘不能・撤退・庇う・回復薬 |
| 関係値 | ペア値(-100〜100)。探索ログ内の出来事で変動。性格相性が初期値 |
| 勘違いイベント | 主人公の行動 → NPCの深読み → 噂 → 評判。主人公の「本音」付き |
| 評判 | 5段階。応募数・質・依頼解放に影響 |
| 経営 | 日給・維持費・治療費・消耗品費 / 依頼報酬・素材売却。赤字は借金+忠誠低下+辞職 |
| 施設 | 宿舎(定員)・治療所(回復)・訓練所(経験値) |
| 画面 | ホーム・冒険者・派遣(依頼+編成)・ログ・施設・財務・募集 |

## 4. 技術構成
- TypeScript / Vite / Vitest。UIは依存なしの素のDOM(小さなhelperのみ)。
- `src/core` は DOM 非依存の純ロジック。`scripts/sim.ts` でUIなしに30日を自動プレイ可能。
- 乱数は mulberry32。すべて `hash(gameSeed, タグ, カウンタ)` から派生 → **同seed・同編成・同条件で同結果**。
- データは `src/data/*.json`(職業・性格・特性・敵・探索地・依頼・イベント・施設・会話・勘違い)。

## 5. データモデル(要点)
- `Adventurer`: id, name, age, level, exp, job, base(8能力), apt{職業→0-100}, growth, personality, traits[{id,revealed}], fatigue, injuryDays, salary, loyalty, status(idle/away)
- 実効能力 = (base + Lv成長) × 職業倍率 × 適性係数(0.65〜1.35, 戦闘能力のみ) × 疲労係数 × 特性補正
- `GameState`: seed, day, gold, rep, adventurers, candidates, relations, facilities, expeditions, history, scenes, ledger …
- `ExpeditionResult`: log[], gold, loot, injuries, expGain, relationDeltas, success, retreated …

## 6. 画面構成
上部に 日付/所持金/評判 と タブ。**派遣画面は「依頼一覧 | 編成スロット | 手持ち冒険者」の3カラム**で、
選ぶだけで推奨戦力・相性警告・日給コストが即時プレビューされる(操作回数最小)。

## 7. 探索シミュレーション
派遣時に全行程を決定論的にシミュレートして結果を保持し、帰還日にログと報酬を開示する(複数パーティー同時派遣が容易)。
1日=3ステップ。各ステップで探索地・依頼・方針・パーティー特性により重み付けしたイベントを抽選。
イベントごとに能力・性格・関係値・乱数で判定し、毎ステップ後にリーダーの性格+方針で撤退判断。
戦闘は速度順ターン制(命中=速度差、与ダメ=攻撃-防御/2、スキルCT、敵AI: ランダム/弱者狙い、庇う、回復薬)。
ログは数値でなく「誰が何をして何を言ったか」中心。関係値変化も行として表示。

## 8. 開発フェーズ
1. 骨組み(seed乱数・型・JSONデータ) 2. 冒険者生成・能力計算 3. 戦闘 4. 探索+ログ 5. 経済・日送り・施設
6. 勘違い・評判 7. UI(派遣サイクル最優先) 8. 自動プレイでバランス調整 9. 仕上げ(セーブ・文章増量)

## 9. 面白さの要点
- 「高能力を並べれば勝ち」にしない: 給与・疲労・相性・性格・適性ミスマッチ(転職で化ける)・未判明特性
- ログの個性: 性格別セリフ、関係値変動の可視化
- 勘違いは主人公を馬鹿にしない: 主人公は合理的に動いているだけ。本音と周囲の解釈のギャップで笑わせる
- 立て直し可能: 借金・辞職・評判低下はあるがゲームオーバーなし

## 10. 切る / 後回し
MVPで切る: 死亡、装備と鍛冶場、市場、酒場・情報屋、恋愛関係、貴族依頼、複数日にまたがる手動介入、セーブスロット複数、サウンド・アニメ。
後回し: 親友/ライバル等の関係タグ演出、貴族・商人イベント、他ギルド、職業追加、装備と素材クラフト。
